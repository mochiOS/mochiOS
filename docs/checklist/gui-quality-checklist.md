# GUI品質の内部チェックリスト

デスクトップと標準アプリの見た目、操作、作業の完了、快適さを手動で確認します。
ViewKitの部品テストと[統合テスト](../testing.md)を継続し、GUIの確認結果をリリース判断へ対応付けます。
繰り返し再発し、手順と期待結果が安定した操作は、自動試験へ追加する候補として記録します。

対象範囲と出荷条件は[Kinako完成チェックリスト](mochios-27-kinako-checklist.md)に従います。
本書は第6・7・11節などの手動確認を具体化するもので、将来機能を新たな必須条件に加えません。

## 確認の進め方

1. 本書を対象ビルドごとの確認記録へコピーし、下の環境欄を埋めます。
2. まずEditの保存、FilesからViewerでの画像表示、権限確認を一通り行います。
3. 採用している部品と標準アプリへ確認範囲を広げ、項目ごとに実際の結果を記録します。
4. 不具合をIssueへ関連付け、修正後は同じ手順と、影響する共通部品の利用箇所を再確認します。

チェックは、記録したビルドと条件で合格を確認してから付けます。初期状態はすべて未検証です。
結果には「未検証・検証中・合格・不合格・対象外・判定待ち」を使います。
対象外には理由を付け、仕様や数値基準が未確定なら判定待ちとして残します。

## ビルドと確認環境

| 記録項目 | 記入内容 |
| :-- | :-- |
| 確認者と日時 | 担当者、確認日。 |
| ビルド | OSの版・build・commit、MWS snapshot、配布イメージのSHA-256、確認するアプリの版。 |
| 環境 | 実機またはKVM、CPU、RAM、GPU、描画経路。KVMではQEMUの版と起動条件も記録します。 |
| 表示 | 解像度、表示倍率、リフレッシュレート、ディスプレイ構成、Light/Dark。 |
| 入力 | 表示言語、キーボード配列、マウス等の機器、IMEの状態。 |
| 開始状態 | OS起動後初回かアプリ再起動後か、ユーザー、設定、開いているウィンドウ。 |
| 確認用データ | ファイル、保存先、権限、ネットワーク等の前提。破棄できる確認用データを使います。 |
| 証拠の保持先 | 記録、画像、動画、ログ、自動試験結果の所在。リリース判定時にも参照できる場所を残します。 |

言語・テーマ・倍率等を変えた結果は、どの条件で確認したかを項目ごとに追えるようにします。
自動試験の成功から、手動確認の欄を合格に変更しません。

## 見た目

- [ ] GUI-V01：ViewKitの標準部品・余白・サイズ・文字の役割を使い、同じ用途の操作部品がアプリ間で揃っています。情報を余白で整理し、不要な区切り線や枠を増やしていません。
- [ ] GUI-V02：ボタン内の文字、入力欄の文字、アイコンの位置と大きさが揃い、部品サイズや倍率を変えても中央揃え・行揃えが崩れません。
- [ ] GUI-V03：VK Symbols、実際のアプリアイコン、既定のフォールバックが適切に表示されます。絵柄が切れず、クリック領域と見た目が対応しています。
- [ ] GUI-V04：通常・ホバー・押下・選択・キーボードフォーカス・無効・エラー・処理中の表示が、各部品の標準規則に揃っています。通常メニューのホバーは灰色で、マウスを外すと解除されます。
- [ ] GUI-V05：Light/Darkの両方で文字・アイコン・状態を判別できます。テーマ変更後に前の配色が残りません。
- [ ] GUI-V06：狭いウィンドウ、文字拡大、長い日本語・英語、長いファイル名でも、主要な操作と説明を読めます。端の部品やポップアップが切れません。
- [ ] GUI-V07：ウィンドウや一覧に正しいアプリ名とアイコンが出ます。日本語・英語の文言と単位が揃い、エラーには対象、原因、次に取れる操作が示されます。

外観の判断では、余白のバランス、情報の優先順位、操作の見つけやすさも記録します。
位置やサイズの不具合が共通部品に由来する場合は、ViewKit側の修正と利用アプリの再確認へつなげます。

## 操作とフォーカス

- [ ] GUI-I01：見えている部品をその位置でクリックできます。無効な部品は反応せず、連打で保存などの処理が意図せず重複しません。
- [ ] GUI-I02：マウスを部品・メニュー・ウィンドウの外へ動かすと、一時的なホバーや押下状態が解除されます。別ウィンドウを操作しても色や入力の捕捉が残りません。
- [ ] GUI-I03：入力先が見て分かり、クリック・Tab移動・ウィンドウ切替後も意図した欄へ入力されます。入力のたびにフォーカスが外れません。
- [ ] GUI-I04：採用したキーボード操作で移動・決定・取り消しができます。EnterやEscが、背後の無関係な画面を操作しません。
- [ ] GUI-I05：IMEの連続入力・変換・候補選択・確定・取り消し、Backspace、キャレット移動、コピー・貼り付け、対応するUndo/Redoを行っても、文字と選択範囲が食い違いません。
- [ ] GUI-I06：確認・保存・エラー画面が対象ウィンドウに隠れず、閉じる・完了・キャンセル後に適切な入力先へ戻れます。無関係なアプリの入力先を奪いません。
- [ ] GUI-I07：メニューやカードを閉じると、その背後のウィンドウやDockを操作できます。見えない操作領域が残りません。
- [ ] GUI-I08：移動・リサイズ・最小化・復元・ウィンドウ切替を繰り返しても表示と操作先が一致します。画面端やStatusBar付近へ移動した後も、必要な操作へ戻れます。

## 作業を通した確認

- [ ] GUI-F01：Editで日本語・英語を含む確認用文書を作成し、Save Asで保存先と名前を指定できます。実ファイルの内容を確認し、閉じて開き直しても編集結果が一致します。保存後に本文へ入力でき、ウィンドウも閉じられます。
- [ ] GUI-F02：既存ファイルへの保存、保存先の変更、キャンセル、未保存文書を閉じる操作を確認します。キャンセルで内容を失わず、上書き対象を取り違えません。
- [ ] GUI-F03：書き込み不可等の失敗条件で保存し、分かるエラーを表示して未保存内容を保持できます。再試行や保存先の変更で作業へ戻れ、失敗を保存済みと表示しません。
- [ ] GUI-F04：Filesから確認用画像を開き、Viewerに画像の内容が表示されます。表示・拡大縮小等の対応する操作を行い、Filesを閉じた後も開いた画像を扱えます。
- [ ] GUI-F05：Dock・アプリ一覧・検索等の採用した入口からアプリを開き、別アプリとの切替後も作業を続けられます。各標準アプリで代表的な作業と終了まで確認します。
- [ ] GUI-F06：権限確認に対象アプリと要求内容が示されます。拒否・キャンセル・一度だけの許可・Always・取消しを、それぞれの仕様の適用範囲で確認し、実際の処理結果と一致します。通常のstdinや貼り付け、別アプリの入力で勝手に承認されません。
- [ ] GUI-F07：通知の表示・終了・一覧・アプリごとの設定、クイック設定の採用項目を操作でき、表示と実際の状態が一致します。メニューやカードを閉じた後も作業を続けられます。

権限確認は[実行許可の仕様](../services/posix-execution-consent.md)と、対象ビルドの要求・許可・取消しの結果を照合します。
未公開の脆弱性は[Security Policy](../../security.md)に従って非公開で扱い、画像や記録へ実ユーザーの秘密を含めません。

## 快適さ

- [ ] GUI-P01：クリック、入力、スクロール、ウィンドウ移動に対する応答と、引っ掛かる条件を記録します。操作可能になる前の空ウィンドウ表示を、起動完了と数えません。
- [ ] GUI-P02：アニメーションの開始・途中・終了と、途中の連続操作・取り消しを確認します。表示の飛び、強いちらつき、不自然な停止、操作待ちが残りません。
- [ ] GUI-P03：待機中と代表操作中のCPU使用率、描画更新、メモリ使用量を確認します。反復操作後に負荷や資源使用量が増え続ける場合は条件と値を記録します。
- [ ] GUI-P04：実機とKVMを区別し、再起動後初回と二回目以降の値を残します。適用する性能目標に対して、環境・測定方法・各測定値を対応付けます。

時間・リフレッシュレート等の目標はKinako完成チェックリスト第5節に従います。
入力遅延、フレーム欠落率、反復回数の未確定な上限を、本書で新たに設定しません。
操作感の所感と数値条件の合否を記録し、基準が未確定な部分は判定待ちとします。

## 項目ごとの確認記録

次の形式で、実際に行った操作と結果を残します。外観は画像、動きや入力は動画、保存は再読込結果等を参照します。

| 記録項目 | 記入内容 |
| :-- | :-- |
| 対象 | GUI項目ID、アプリ、画面、対応する完成チェックリストの項目ID。 |
| 条件 | 上記のビルド・環境と、この項目で変更した条件。 |
| 手順 | 開始状態、入力データ、操作順、失敗条件、確認した回数。 |
| 合格条件 | 上の条件を具体化した、確認可能な期待結果。 |
| 実際の結果 | 表示、入力先、保存内容、測定値等。 |
| 結果 | 未検証。確認後に該当する結果へ変更します。 |
| 証拠 | 画像、動画、ログ、自動試験結果等の保持先。 |
| Issueと再確認 | 再現手順、影響範囲、関連Issue、修正commit、再確認したビルドと結果。 |

## レビューの判定

操作不能、データ消失・誤保存、権限の誤承認等があれば、該当項目を不合格として記録します。
見た目の問題、未検証、対象外、判定待ちも残し、チェック済みの件数だけで全体を合格にしません。
最終判断はKinako完成チェックリスト第21節へ、対象ビルドと確認範囲を付けて引き継ぎます。

| 判定項目 | 記入内容 |
| :-- | :-- |
| 全体の判定 | 未検証。 |
| 確認範囲 | 確認したアプリ、GUI項目ID、環境の組合せ。 |
| 残る問題 | 未解決Issue、未検証・対象外・判定待ちの項目と理由。 |
| 再確認 | 修正後に確認する範囲と、その結果。 |
| レビュー担当と日時 | 判定を行った担当者、日時、記録の保持先。 |
