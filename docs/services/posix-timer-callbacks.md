# タイマーのスレッド通知

`SIGEV_THREAD`に必要な通知受信を、ユーザー空間のPOSIX層に追加します。
カーネルのABIやシグナル番号の予約は追加しません。

## サービスとIPC

`Notification::Thread { cookie }`は、プロセス内の通知レジストリを指す
不透明なトークンです。関数ポインタ、sigvalの値、pthread属性はサービスへ
送りません。タイマーの所有者は認証済みIPCのプロセス情報で決まり、
UIDが0でも別プロセスの通知は取得できません。

`OP_TIMER_THREAD_WAIT`の要求はバージョンと予約領域だけです。
返信はバージョン、タイマーID、トークン、overrun数です。
受信スレッドの識別はネイティブIPCの送信元情報から行い、登録済みの
プロセスイメージとスレッドを確認します。添付Handleは受け付けません。

未通知なら返信を保留します。保留要求はプロセスごとに1件、全体で
1024件に制限し、領域を予約してから通知を選択します。
再試行時は元のエンドポイントとイメージを再検証します。
時計の観測失敗やexecを成功扱いにしません。

期限の観測は既存のタイマーリアクターを使います。通知の選択と消費は
別処理とし、現在のCPU・時刻を再観測したうえで、返信が送信できた時だけ
消費とoverrunの確定を行います。失敗した返信は通知を残します。
選択順は未処理通知の発生順で、低いタイマーIDの再発火による飢餓を防ぎます。
削除・再設定で破棄した通知を、新しいタイマーへ付け替えません。

`posix-client::timer_wait_callback`がこの受信を提供します。
汎用Streamの枠やアプリケーションのシグナルを消費する設計ではありません。
通知返信後にプロセスが失われた場合の配送保証はありません。

## libcへの接続

newlibの`timer_create(..., SIGEV_THREAD, ...)`は、関数・sigvalとpthread属性を
検査付きでコピーし、プロセス内のレジストリへ保存します。送信する値は
再利用しないトークンだけです。属性の元メモリを通知時まで参照しません。
属性がNULLなら標準のスタック・ガードを使い、通知スレッドはdetachedにします。
joinable属性が指定された場合も、通知にjoinの所有者はないためdetachedへ
正規化します。その他の属性の対応範囲は既存pthread実装に従います。

受信スレッドはプロセスごとに必要時に1本生成し、キャンセルを無効化し、
アプリケーションのシグナルをブロックします。受信後にdetached pthreadを
生成し、そのスレッドでアプリケーション関数を呼びます。アプリの関数は
受信スレッド上では実行しません。callbackの初期シグナルマスクもこの
内部スレッドのマスクを継承します。

ジョブには固定領域を使います。関数を呼ぶ前にジョブの領域と内部ロックを
解放するため、callback内の再入やpthread_exitでヒープの引数が残りません。
pthread生成失敗時はジョブを解放し、受信済み通知を保持して待機後に再試行
します。タイマーを削除済みなら遅延ジョブは呼び出しません。実行を開始した
callbackの強制終了はしません。作成失敗時はローカル登録を取り消し、
サービス側タイマーの削除を既存のrollback処理へ渡します。

スレッドCPU時計に結び付くcallbackは対象スレッドの終了時に退役します。
forkの子では通知レジストリ・ジョブ・内部受信スレッドの識別を破棄し、
新しいタイマーの作成時に受信を開始し直します。トークンの発行済み上限は
保持します。最後のアプリケーションpthreadが終了した場合、内部受信スレッド
だけでプロセスを生かし続けません。判定中はスレッド生成を凍結します。

ホスト試験は`services/posix/tests/support/timer_callback.rs`、
実IPCの遅延返信・全シグナルをブロックした受信・overrun・削除の試験は
`services/posix/tests/native_timer_callback.rs`です。
libc側の属性コピー・ジョブ寿命は`timer_callback_runtime.rs`、
実newlibの再入・pthread_exit・反復生成・作成失敗・forkは
`native_sigev_thread.c`で確認します。POSIX全体への適合を示すものではありません。
