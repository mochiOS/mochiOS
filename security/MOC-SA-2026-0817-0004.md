# MOC-SA-2026-0817-0004

| 項目            | 内容                         |
|---------------|----------------------------|
| 状態            | Reported                   |
| 深刻度           | Critical                   |
| 影響を受けるコンポーネント | mnuカーネル                    |
| 影響を受けるバージョン   | 0.12-rc1および0.12開発版          |
| 修正済みバージョン     | 未修正                        |
| クレジット         | 内部監査                       |

## 概要

mnuカーネルの`ipc_wait`処理において、呼び出し元が指定されたIPC Endpointを所有しているか、
または同Endpointから受信する権限を持つかを検証しないまま、対応するスレッドのmailboxを読み出せる問題があります。

Endpoint handleは連番で割り当てられ、サービス間で受け渡されるため、攻撃者が有効なhandleを推測または取得できる可能性があります。

## 影響

非特権プロセスが別プロセスまたはシステムサービス宛のIPC requestを読み取り、mailboxから取り除く可能性があります。
これにより、IPC payloadの漏えい、requestの消失によるサービス拒否、sender情報の取得、
および正規サービスより先に応答することによる応答偽装につながる恐れがあります。

認証token、Capability request、ファイル操作、プロセス起動などのIPCを横取りできる場合、
サービス間の機密性と完全性が失われ、権限昇格やサンドボックス脱出につながる可能性があります。

## 回避策または緩和策

未修正のカーネルでは、信頼されていないプロセスを実行しないでください。
`ipc_wait`で呼び出し元以外が所有するEndpointを指定する経路を無効化し、
機密性が必要なProtocolでは追加のsender検証とrequest token検証を行ってください。

## 修正情報

未修正です。

Endpoint recordへ所有Processと受信権限を記録し、`ipc_wait`、`ipc_recv`、`ipc_reply`の全経路で
呼び出し元との対応を検証する必要があります。Endpoint handleには十分な予測困難性または世代管理を持たせ、
他プロセスのmailboxを直接指定できる互換経路は削除する必要があります。
