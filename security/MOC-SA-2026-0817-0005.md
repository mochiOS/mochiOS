# MOC-SA-2026-0817-0005

| 項目            | 内容                         |
|---------------|----------------------------|
| 状態            | Reported                   |
| 深刻度           | High                       |
| 影響を受けるコンポーネント | mnuカーネル                    |
| 影響を受けるバージョン   | 0.12-rc1および0.12開発版          |
| 修正済みバージョン     | 未修正                        |
| クレジット         | 内部監査                       |

## 概要

mnuカーネルの複数のsyscallにおいて、ユーザープロセスが指定した長さまたは要素数を十分に制限せず、
その値をカーネルheap上の`Vec`確保へ使用する問題があります。

少なくとも標準出力および標準エラーへの`write`、consoleおよびlog出力、Event poll、
directory entry取得処理に同種の無制限または過大な確保経路が存在します。

## 影響

非特権プロセスが巨大な長さを指定するだけで、カーネルheapの枯渇またはallocation failureを引き起こせます。
allocation failureがカーネルpanicまたは停止になる構成では、任意のアプリケーションから
システム全体に対するサービス拒否が可能です。

繰り返し呼び出すことで、単一requestでは上限内であってもカーネルメモリを継続的に消費する可能性があります。

## 回避策または緩和策

未修正のカーネルでは、信頼されていないプロセスを実行しないでください。
該当syscallをユーザーランドから直接利用できないようにするか、入力長を小さい固定上限へ制限してください。

## 修正情報

未修正です。

すべてのsyscallでユーザー指定長を`usize`へ変換する前に検証し、操作ごとの固定上限を適用する必要があります。
大きなI/Oは固定長bufferによるchunk処理へ変更し、動的確保には`try_reserve`を使用して
allocation failureをerrnoとして呼び出し元へ返す必要があります。
