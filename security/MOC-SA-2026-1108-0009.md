# MOC-SA-2026-1108-0009

| 項目 | 内容 |
| :-- | :-- |
| タイトル | 入力購読の認可漏れによるフォーカス外のキー入力取得 |
| 状態 | Reported・未修正（静的確認） |
| 深刻度 | High |
| 影響を受けるコンポーネント | input.service |
| 確認したバージョン | services `a2c9b3a69967fdc611a75994ca4f1a3f9fc926e6` |
| 修正済みバージョン | なし |
| クレジット | 内部監査 |

## 概要と根拠

`services/input/src/main.rs`の受信ループは、公開IPCからの`SUBSCRIBE_OPCODE`を
Capabilityやセッションの検査なしで`handle_subscribe_message`へ渡します。
同関数は要求内のendpointを購読先配列へ登録し、送信元がそのendpointの所有者であることも確認しません。

`process_keyboard_byte`はキーコード、押下・解放、修飾キー、文字コードを生成し、
`send_event_reliably`が全購読先へ配信します。配信時のフォーカス、セッション、
`input.keyboard.global`の照合もありません。ポインターも同じ購読先へ配信します。
対応するglobal Capabilityは`core/crates/abi/src/capability.rs`に定義されています。

## 成立条件と影響

公開IPCでinput.serviceへ到達でき、自身の受信用endpointを持つ一般プロセスが、
空き購読枠へ登録すると、そのプロセスにフォーカスがなくても入力イベントを取得できます。
キーロギング、他アプリの入力内容の漏えい、全8枠を占有することによる正規購読の妨害につながります。
保護された認証画面の入力も、この配信経路では除外していません。

生入力の注入用endpointと承認用の専用ストリームには別の保護があります。
それらの保護が破られたと主張するものではなく、公開の購読経路自体の認可漏れです。
実データの採取、実行時の攻撃実証は行っていません。

## 修正方針

全入力の購読には明示委譲された購読Handle、またはglobal入力権限を必須とし、
送信元の実行主体・寿命と購読先を結び付けます。送信先番号の申告だけで登録してはいけません。
通常アプリにはcompositorからフォーカス対象へのイベントだけを配送し、
認証・承認中の入力を一般購読から分離します。失効・終了時に枠を回収します。
カーネルにサービス名やログイン方針を追加する必要はありません。

## 緩和策と確認範囲

修正までは、入力購読を信頼済みのcompositor等に限定し、未信頼コードを同時に実行しない運用が必要です。
受信分岐、購読登録、キー生成、配信先までをソースで確認しました。
試験の追加・実行、ビルド、KVM起動は行っていません。
