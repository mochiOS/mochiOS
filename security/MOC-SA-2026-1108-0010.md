# MOC-SA-2026-1108-0010

| 項目 | 内容 |
| :-- | :-- |
| タイトル | Hypercall入口でゲストCPLを検査せずOSドメインの停止を許可 |
| 状態 | 修正実装済み・動作未検証 |
| 深刻度 | High |
| 影響を受けるコンポーネント | mBootのVMX/SVM Hypercall受付 |
| 確認したバージョン | mboot `1cd255ffa42d32d7c69333fceffe2d27f4289f9c` |
| 修正済みバージョン | 未リリース。`Fix MOC-SA-2026-1108-0010`で修正 |
| クレジット | 内部監査 |

## 概要と根拠

`mboot/src/arch/x86_64/vmx.rs`の`VMCALL_EXIT_REASON`と
`mboot/src/arch/x86_64/svm.rs`の`SVM_EXIT_VMMCALL`は、ゲストの現在の特権レベルを
検査せず`VmExitReason::Hypercall`を返します。
`mboot/src/lib.rs`の`VmExit`にも呼出時CPLを保持するフィールドがありません。

`mboot/src/main.rs`の受付ループは、この結果をドメイン単位の要求として扱います。
`HypercallNumber::Shutdown`ではゲスト内の呼出主体を確認せず、資源を解放して当該ドメインを停止します。
これに先立つmnuのProcessHandleやCapabilityの検査はありません。

## 成立条件と影響

mBootの管理下でmnuが動き、そのドメイン内のCPL3で未信頼のネイティブ命令を実行できる構成が対象です。
ゲスト内のユーザープロセスが直接Hypercall命令を実行すると、少なくともOSドメイン全体の停止へ到達します。
通常のプロセス終了権限をドメイン全体への操作へ拡大してしまっています。

他のHypercallも同じ入口を共有します。物理メモリ、Grant、割り込み等への追加影響は個別評価が必要です。
この記録はハイパーバイザーのホストメモリ制御や、ホストへの脱出を実証したものではありません。

## CPU仕様との照合

VMX non-rootのVMCALLはVM exitを発生させるため、ゲスト内の通常の特権命令制限だけでは防げません。
AMDもVMMCALLのCPL検査をVMM側の判断に委ねています。

- [Intel SDM Volume 3C](https://cdrdv2-public.intel.com/671506/326019-sdm-vol-3c.pdf) §26.1.2。
- [AMD64 APM Volume 2](https://docs.amd.com/api/khub/documents/sD1_QL~h4Afq2_tvzxqqSQ/content) §15.18。

## 修正方針・緩和策

VMCS/VMCBが保持するゲスト実行状態から呼出時CPLを取得し、カーネル専用Hypercallを
CPL0に限定します。ユーザー呼出を設ける場合は、別の限定された操作として明示的に設計します。
ドメインの役割・資源範囲検査も継続し、CPL確認で代用しません。
サービス名、パス、POSIXサービスの存在をmBootやmnuへ教える修正は不要です。

修正前はmBoot管理下で未信頼のゲストユーザープロセスを実行しないでください。
命令仕様とソース経路を照合しました。停止命令の実行、試験追加、ビルド、KVM起動は行っていません。

## 修正実装

VMXの保存済みCS／CR0／RFLAGS、SVMの保存済みCPLから実際の特権レベルを取得します。
APへ固定したvCPUは、その所有CPUへ照会を配送します。
全Hypercallのdispatch前にCPL0を要求し、取得失敗も拒否します。
拒否は副作用なしのUnsupported応答として命令を進め、一般プロセスの不正要求でドメインを停止しません。
試験の追加・実行は行っていません。
